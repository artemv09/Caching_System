# Caching System

`Caching System` — учебный проект на C++ для моделирования и сравнения различных алгоритмов кэширования.

Проект позволяет создавать **одноуровневые и многоуровневые системы кэша**, выбирать алгоритм для каждого уровня, работать в режимах **Inclusive** и **Exclusive**, подавать собственную последовательность запросов или автоматически проверять конфигурации на различных типах нагрузки.

Для каждого запуска подсчитывается количество попаданий в кэш и промахов, что позволяет сравнивать различные алгоритмы и их комбинации.

---

## Реализованные алгоритмы

В проекте реализованы пять алгоритмов кэширования:

| Алгоритм | Основная идея | Реализация |
|---|---|---|
| **LRU** | вытесняется элемент, который дольше всего не использовался | `lru_cach.hpp` |
| **LFU** | вытесняется элемент с наименьшей частотой обращений | `lfu_cach.hpp` |
| **2Q** | новые и часто используемые элементы обрабатываются раздельно | `2Q_cach.hpp` |
| **ARC** | адаптивно балансирует недавно и часто используемые данные | `arc_cach.hpp` |
| **LIRS** | учитывает историю повторного использования элементов | `lirs_cach.hpp` |

Также в проекте реализован алгоритм **OPT/MIN**:

```text
opt_cach.hpp
```

OPT используется как теоретический ориентир: он заранее знает будущую последовательность запросов и вытесняет элемент, который понадобится позже остальных.

---

## Многоуровневый кэш

Основная система может содержать несколько уровней:

```text
Request
   |
   v
  L1
   |
   v
  L2
   |
   v
  L3
```

Количество уровней задаётся пользователем.

Каждый уровень может использовать собственный алгоритм.

Например:

```text
L1 — LRU
L2 — ARC
L3 — LIRS
```

Таким образом можно сравнивать как одинаковые алгоритмы на всех уровнях, так и их различные комбинации.

Логика многоуровневой системы находится в:

```text
multi_level_cache.hpp
```

---

## Inclusive и Exclusive

Проект поддерживает два варианта организации многоуровневого кэша.

### Inclusive

В Inclusive-режиме данные верхнего уровня также присутствуют на нижних уровнях:

```text
L1 ⊆ L2 ⊆ L3
```

Если страница находится в L1, её копия также хранится на нижних уровнях.

---

### Exclusive

В Exclusive-режиме одна страница хранится только на одном уровне кэша.

При вытеснении данные могут перемещаться между уровнями:

```text
L1 → L2 → L3
```

За счёт этого уровни не хранят одинаковые resident-страницы и эффективнее используют общую доступную ёмкость.

# Сборка проекта

Для работы необходимы:

- CMake;
- компилятор с поддержкой C++20.

Все команды выполняются из корневой папки проекта.

## Inclusive

```bash
cmake -S . -B build-inclusive \
  -DCACHE_MODE=Inclusive \
  -DBUILD_CACHE_APP=ON \
  -DBUILD_BENCHMARK=ON \
  -DBUILD_TESTING=OFF

cmake --build build-inclusive
```

## Exclusive

```bash
cmake -S . -B build-exclusive \
  -DCACHE_MODE=Exclusive \
  -DBUILD_CACHE_APP=ON \
  -DBUILD_BENCHMARK=ON \
  -DBUILD_TESTING=OFF

cmake --build build-exclusive
```

Inclusive и Exclusive собираются в разные папки, поэтому обе версии проекта могут существовать одновременно.

# Ручной режим

Ручной режим позволяет самостоятельно задать:

- количество уровней;
- алгоритм каждого уровня;
- размер каждого уровня;
- количество запросов;
- последовательность ключей.

Количество уровней и названия алгоритмов задаются в файле:

```text
config.txt
```

Например:

```text
2
LRU
LFU
```

Это означает:

```text
L1 — LRU
L2 — LFU
```

Доступные названия:

```text
LRU
LFU
2Q
ARC
LIRS
```

После этого запускается нужная версия программы.

### Inclusive

```bash
./build-inclusive/caching_system
```

### Exclusive

```bash
./build-exclusive/caching_system
```

После запуска через консоль вводятся размеры уровней, количество запросов и сами ключи.

Для конфигурации:

```text
L1 — capacity 2
L2 — capacity 4
```

и восьми запросов ввод будет выглядеть так:

```text
2 4
8
1 2 1 3 4 1 2 4
```

Программа последовательно обрабатывает запросы и выводит статистику попаданий по уровням кэша.

Если используется **LIRS**, вместе с размером соответствующего уровня необходимо также указать параметр HIR.

# Автоматическое тестирование на разных паттернах

В проекте предусмотрен отдельный режим для массового сравнения алгоритмов.

Вместо ручного ввода последовательности программа автоматически создаёт различные типы нагрузки.

Например, могут генерироваться:

```text
1 2 3 4 1 2 3 4 ...          циклические обращения

1 1 1 2 2 2 3 3 3 ...        серии повторов

1 2 3 4 3 2 1 ...            движение по рабочему набору туда и обратно

HOT HOT HOT ... SCAN ...      популярные данные и сканирование новых

A A A A → B B B B             смена рабочего набора
```

Также используются:

- равномерно случайные запросы;
- нагрузки с горячими и холодными ключами;
- кратковременные всплески популярности;
- изменение популярности во времени;
- последовательности с различной временной локальностью;
- неравномерные распределения запросов.

Один тип нагрузки может создаваться с различными размерами рабочего набора и параметрами, поэтому для каждой конфигурации выполняется множество отдельных прогонов.

Генераторы последовательностей находятся в:

```text
tests/request_patterns.hpp
```

---

## Запуск автоматических прогонов

### Inclusive

```bash
./build-inclusive/benchmark_test
```

### Exclusive

```bash
./build-exclusive/benchmark_test
```

После запуска необходимо ввести:

```text
L — количество уровней
K — количество выбранных алгоритмов
N — количество запросов в каждом паттерне
```

Затем вводятся названия алгоритмов и размеры уровней.

Например:

```text
2 2 100
LRU LFU
2 4
```

Здесь:

```text
2   — два уровня
2   — выбраны два алгоритма
100 — сто запросов в каждом паттерне
```

Программа автоматически проверит все комбинации выбранных алгоритмов:

```text
LRU / LRU
LRU / LFU
LFU / LRU
LFU / LFU
```

Каждая конфигурация получает одинаковые входные последовательности, поэтому результаты можно сравнивать между собой.

Для каждого варианта выводятся попадания по уровням, общее число попаданий и промахов, а также результат OPT для сравнения.

Если среди выбранных алгоритмов используется **LIRS**, для соответствующих уровней также вводится параметр HIR.

# Unit-тесты

Для автоматической проверки корректности реализации используется **GoogleTest**.

Тестовая сборка создаётся отдельно:

```bash
cmake -S . -B build-tests \
  -DBUILD_CACHE_APP=OFF \
  -DBUILD_BENCHMARK=OFF \
  -DBUILD_TESTING=ON

cmake --build build-tests
```

Если GoogleTest уже установлен в системе, будет использована установленная библиотека.

Если GoogleTest не найден, он будет автоматически загружен при первой сборке. В этом случае для первой сборки тестов потребуется подключение к интернету.

После загрузки повторные сборки обычно не требуют повторного скачивания библиотеки.

---

## Запуск unit-тестов

Все тесты можно запустить командой:

```bash
./build-tests/unit_tests
```

или через CTest:

```bash
ctest --test-dir build-tests --output-on-failure
```

В проекте уже есть unit-тесты для реализованных алгоритмов и многоуровневого кэша.

---

## Добавление своего unit-теста

Для собственных тестов предусмотрен файл:

```text
tests/my_test.cpp
```

В него можно добавить обычный GoogleTest:

```cpp
TEST(MyCache, SimpleTest)
{
    // Arrange
    // подготовка данных

    // Act
    // выполнение проверяемой операции

    // Assert
    // проверка результата
}
```

После изменения файла необходимо пересобрать тесты:

```bash
cmake --build build-tests
```

и снова запустить:

```bash
./build-tests/unit_tests
```

## Цель проекта

Проект предназначен для изучения и сравнения алгоритмов кэширования.

Он позволяет экспериментировать с:

- LRU, LFU, 2Q, ARC и LIRS;
- одноуровневыми и многоуровневыми кэшами;
- Inclusive и Exclusive организацией уровней;
- различными размерами кэшей;
- разными комбинациями алгоритмов;
- собственными последовательностями запросов;
- автоматически создаваемыми паттернами нагрузки;
- сравнением количества попаданий и промахов;
- проверкой реализации с помощью unit-тестов.
